# 沒有金流的第一階段：VaultDraw 還能推什麼

寫給自己看的。問題是：「如果沒有儲值、沒有金流，這平台還有什麼特別之處可以推廣？」

查核日 2026-09-15。依據：讀碼（`src/router/index.ts`、`src/pages`、`src/components`、
`server/src/routes`）、`docs/taiwan-scene.md`、`docs/payment-models.md`、
`docs/cardbase-comparison.md`、`docs/cert-verification-alternatives.md`，外加少量網路補查。

> 這份文件只談「不碰錢」的做法。儲值、點數換現金、平台代收代付，一律不在討論範圍。

---

## 0. 先講結論

**有得推，但推的不是「交易」，是「登記」。**

第一階段真正站得住、而且別人沒有的東西只有一個核心：
**同一個鑑定編號（同一家鑑定公司），全站只能被一個人登記、同時只能有一筆刊登。**
這是資料庫層的唯一約束，不是文案。卡拍拍、iCard、Yahoo 把「PSA 10」當標籤；
皮卡屋、呼卡、Cardex Go 的收藏是各自打字、互不相干。沒有一家在「全站」層級管這件事。

圍著這個核心，已經做好的卡冊、搜尋、同款卡歸納、公開分享連結、卡片來歷，
合起來就是一個說得清楚的產品：**台灣鑑定卡的「公開登記簿」＋ 刊登佈告欄。**

**但有兩件事要先講清楚，否則推出去會出事：**

1. **第一階段的核心流程現在其實走不通。**
   - 市場的「刊登」要押點數保證金（`server/src/routes/public.ts` 上架那段的 `INSUFFICIENT_POINTS`），
     沒有點數就刊登不了。
   - 買家要**先用點數下單**，才看得到賣家聯絡方式（`server/src/routes/orders.ts` 的 `canSeeSeller`）。
   - **公開卡冊只列 `stashed`／`listed` 的卡**（`server/src/routes/social.ts`），
     自己登記的卡是 `in_book`，**分享連結打開是空的**。
   這三件不改，第一階段就沒東西可推。見第 5 節。
2. **站上有幾頁寫了第一階段做不到的保障**（`TradeProtectionPage.vue` 寫了託管凍結、
   「編號必須在鑑定機構查得到才准上架」、上傳圖做感知雜湊比對——後兩項沒有實作；
   首頁與 SEO 文案仍是「點數先鎖在平台」）。推廣前一定要先收掉或改寫。

## 1. 功能盤點：哪些不需要金流就能用

標註：**可用**＝現在直接能用；**小改**／**中改**＝需要改才適合第一階段；**不能用**＝依賴金流或抽卡。

| 功能 | 在哪 | 對玩家的價值（白話） | 狀態 |
|---|---|---|---|
| 卡片登記（目錄挑卡／手填＋正面照） | `CardUploadPage`、`routes/cardbook.ts` | 從卡片目錄點選，不用自己打卡名卡號；目錄沒有的卡拍正面照也能登記 | **可用** |

## 2. 一句話定位（候選）

1. **「台灣鑑定卡的公開登記簿：一個編號，只屬於一個人。」**（推薦）
   打的是別人都沒有的那一格，而且這句話是真的——資料庫層保證。
2. **「把你的鑑定卡收藏變成一條連結，貼到群組就能看、就能談。」**
   打的是使用情境，最好懂；但卡拍拍、cardbase.io 也在做收藏冊，差異要靠第 1 句補。
3. **「刊登鑑定卡的地方：可以篩、可以搜，不會被洗版洗掉。」**
   打的是對 FB／LINE 社團的痛點；適合在社團裡講，不適合當品牌主句。

**建議組合**：品牌主句用 1，社群貼文用 2，跟賣家講的時候用 3。

**不要用的說法**：「安全交易」「交易保障」「驗證真偽」「零手續費」
（前三個做不到；第四個在不碰錢的前提下本來就不是讓利，見 `cardbase-comparison.md` D-5）。

## 3. 跟三種對手各比一次

### 3.1 臉書社團／LINE 群

台灣高價卡的主流成交其實在這裡（`taiwan-scene.md` 2.1）。**你真正要打的是這個習慣，不是卡拍拍。**

| 我們多了 | 我們少了 |
|---|---|
| 每筆刊登有固定網址，不會被新貼文沖掉 | 人潮。群組裡已經有幾千個買家在線 |
| 依鑑定公司、分數、價格篩選與搜尋 | 即時喊價、+1、團購那種節奏 |
| 同一編號全站唯一，同一張卡不能被兩人同時刊登 | 熟人信任：群組管理員、老面孔、面交 |
| 一本整理好的卡冊，一條連結給人看 | 群組內的「黑名單」口耳相傳 |
| 聯絡方式旁固定出現防詐提醒與檢舉入口 | — |

**策略**：不要叫人離開群組，要讓 VaultDraw 的連結**變成群組貼文裡的附件**。
「我要賣的卡在這，編號已登記」這句話在群組裡就有用。

### 3.2 卡拍拍（還有 iCard、TCGSTORE）

| 我們多了 | 我們少了 |
|---|---|
| 鑑定編號全站唯一（它們把鑑定當卡況標籤，`taiwan-scene.md` 第 2 節） | **站內金流與履約保證**（卡拍拍走紅陽託管；iCard 走綠界、收到後 7 天放款） |
| 公開卡冊一條連結、免裝 App、沒帳號也能看 | 實名認證（iCard 上架前強制實名） |
| 刊登時不必把人留在站內——你本來就在群組裡談 | 評價系統、成交紀錄（TCGSTORE 分 7/30/90/365 天） |
| — | 行情走勢（卡拍拍收藏冊有漲跌） |
| — | App、推播、既有使用者量 |

**注意**：卡拍拍明文**禁止導向站外交易**，它的使用者被教育成「站外＝危險」。
你的模式正好是站外成交，所以**不能跟它比安全**，只能比「登記」與「分享」。

### 3.3 卡冊／行情工具（皮卡屋、呼卡、Cardex Go、cardbase.io）

| 我們多了 | 我們少了 |
|---|---|
| 登記是全站共用的，一個編號不能被兩個人都說是自己的 | **行情資料**（皮卡屋、呼卡都有 PSA 行情，資料來自 SNKRDUNK／eBay） |
| 卡冊直接就能刊登、就能分享 | 拍照辨識卡片（呼卡、皮卡屋都有） |
| 網頁即用，不用裝 App、不用加 LINE Bot | 損益計算、持倉追蹤 |
| 目前免費（沒有訂閱牆） | 已經驗證有人願意付費（皮卡屋、呼卡都在收訂閱） |

**cardbase.io 要特別盯**：它是香港的「資訊交換平台」，不經手款項，
模式跟你的第一階段幾乎一樣，而且已經在台北卡展擺攤、市集頁用 NT$ 標價
（`cardbase-comparison.md` 結論六）。它的使用者基數目前很小，但它是最像你的那一個。
差異同樣只能打在「編號全站唯一」與「台灣本地」。

## 4. 最值得推的四個賣點，以及怎麼展示

### 賣點一：你的編號，別人登記不了

**講法**：「PSA／BGS／ARS 編號在 VaultDraw 全站只能登記一次。你先登記，這號碼在這裡就是你的。」

**怎麼展示**
- 拍一支 15 秒螢幕錄影：登記一張卡 → 換帳號輸入同一個編號 → 畫面跳出「已經登記在別人名下」。
  這一支片就是整個產品的說明書，發 Threads、IG Reels、群組都用它。
- 在群組賣卡時，文案範例：「這張已在 VaultDraw 登記，編號只在我名下，連結在此。」
- **一定要附一句**：「登記只代表這號碼在站上屬於我，真偽請到鑑定機構官網查。」

### 賣點二：一條連結，整本卡冊

**講法**：「收藏不用再一張一張傳照片。一條連結，沒帳號也能看；不想給看了隨時關掉，連結立刻失效。」

**怎麼展示**（需先完成第 5 節 #1、#5）
- 做一張「卡冊分享圖」：持有人名稱＋前 9 張卡縮圖＋QR code，存成圖片，
  直接發 IG 限動、Threads、LINE 群。圖片比連結更容易被按。
- 個人 IG／Threads 簡介放卡冊連結，當收藏帳號的「作品集」。
- 強調隱私設計：公開頁**不顯示鑑定編號**，不怕被抄號。

### 賣點三：刊登不會被洗掉，買家找得到

**講法**：「群組貼文一小時就沉了。這裡每張卡有自己的網址，買家可以用 PSA 10、價格區間篩出來。」

**怎麼展示**
- 截一張「篩選 PSA 10、價格 5,000～20,000」的結果畫面，對比群組裡往上滑找貼文的痛。
- 每週在自己的社群帳號貼「本週新刊登的 PSA 10」（連回市場篩選頁），做成固定欄目。

### 賣點四：同款卡自動整理，大量收藏也翻得動

**講法**：「上百張卡？搜卡名、搜編號、只看重複的，一鍵每款留一張。」

**怎麼展示**
- 對象是手上有很多裸卡與鑑定卡混放的中重度玩家、代送業者的客人。
- 螢幕錄影：搜尋編號 → 秒找到；打開「只看重複」→ 同款疊成 ×N。

### （可選）賣點五：平台不保管你的卡，也不經手你的錢

這是事實，也回應了「店家倒閉、卡跟錢都在第三方手上」那類事件的焦慮
（`taiwan-scene.md` 第 5 節）。**但只能這樣講，不能延伸成「所以比較安全」**——
站外付款被騙，平台一樣追不回來。建議只放在 FAQ，不當主打。

## 5. 冷啟動：前 100 個用戶從哪來

沒有廠商、沒有金流時，**先要的是「有卡的人」，不是買家**。
卡冊與登記可以一個人用得很開心；市場要等供給夠了才有意義。

| 順序 | 管道 | 目標人數 | 要準備什麼 |
|---|---|---|---|
| **1** | **自己＋身邊有鑑定卡的朋友** | 10～20 | 先把自己的收藏全部登記、公開卡冊；讓首頁與市場不是空的。每人一對一幫他登記前 5 張 |
| **2** | **鑑定代送業者** | 2～3 家業者，帶出 30～50 人 | 業者的痛點是「客人的卡送回來後怎麼交付與展示」。給業者一個說法：送回來的卡請客人自己登記進 VaultDraw，編號先佔好。準備一頁給業者轉發的圖文教學（LINE 格式）。**不要談分潤或代收款** |
| **3** | **FB 鑑定卡社團、LINE 社群** | 20～30 | 先讀版規，多數禁止廣告。不發廣告帖，改成「賣卡貼文附卡冊連結」自然露出；找 1～2 位管理員私訊，提供「群組專用：刊登用連結」的用法。準備賣點一那支 15 秒影片 |
| **4** | **卡店、店家賽、地區賽** | 10～20 | A5 立牌＋QR code：「現場掃碼，30 秒登記你的 PSA 編號」。準備手機上能順跑的登記流程（LINE 登入優先）。先談 1 家願意放立牌的店，不必談合作條件 |
| **5** | **卡展（例如三創卡展、888 卡牌市集攤位）** | 10～20 | 不一定要擺攤；可以跟擺攤的賣家合作，在他的卡旁放「已登記」小卡＋QR。準備名片大小的說明卡 |
| **6** | **Threads／IG 收藏帳號、巴哈姆特 PTCG 板** | 零星 | 固定欄目（每週 PSA 10 刊登、有趣的登記數據），不硬推。巴哈發文注意板規 |

**第一步建議**：先做 1 和 2——把自己與幾位朋友的卡登記滿，然後帶著完整卡冊去找**一家**代送業者。
業者一家就能帶來一批「剛拿到新編號、正需要展示」的人，這群人最符合賣點一。

**每個管道都要帶的三樣東西**：15 秒「編號擋重複」影片、卡冊分享圖範例、
一段誠實說明（第 7 節那幾句）。

## 6. 為了推廣要改的東西（依投報排序）

先分兩類：**不改就上不了線的**，與**改了推廣效果會好很多的**。

### 6.1 上線前必要

| # | 做什麼 | 為什麼 | 工作量 |
|---|---|---|---|
| A | **公開卡冊納入 `in_book` 的卡**（`social.ts` 的 `status in (...)` 與 `cardbookSummary`；「可談交易」的判斷也要跟著改） | 第一階段所有卡都是登記來的，現在分享連結打開是空的 | **小** |
| B | **刊登不再要求點數保證金**；裸卡上限改用元或暫時取消（`public.ts` 上架段、`shared/escrow.ts`） | 現在沒點數就刊登不了 | **中**（牽動上架頁文案與既有 regress 測試） |
| C | **掛單頁：登入後直接顯示賣家聯絡方式＋ScamNotice**，拿掉「買下」按鈕與點數文案（`MarketListingPage`、新增一支登入才回聯絡方式的端點） | 第一階段的核心動作本身不存在 | **中** |
| D | **價格單位由「點」改成「元（參考售價）」**，市場、上架頁、篩選訊息 | 「點」會讓人以為要儲值 | **小～中**（字串多、分散） |
| E | **收掉抽卡、錢包、儲值、交易邀約、交易保護頁的入口；改寫首頁與 `seo-routes.json`** | 這些頁面在描述第一階段做不到的保障，對外就是承諾不實 | **小** |

## 7. 誠實列出弱點，以及怎麼說不傷信任

原則：**先講自己做不到的，再講自己做得到的。** 不要讓使用者自己發現。

| 弱點 | 實際情況 | 建議的說法 |
|---|---|---|
| 沒有金流、沒有託管 | 平台不經手錢，站外被騙追不回來 | 「VaultDraw 不經手付款，也無法追回站外匯款。建議面交，或確認身分與卡片後再付款。」（`ScamNotice.vue` 已寫了同義提醒，目前掛在訂單頁，要搬到掛單頁） |
| 無法自動驗證鑑定編號 | PSA API 拿不到授權，其他機構沒有 API | 「站上不會自動查驗編號。每張卡都附官方查詢連結，請自己查一次。」 |
| 編號唯一 ≠ 卡是真的 | 真號碼可以被做到假殼上 | 「編號唯一，只代表同一號碼在站上不會有兩個人登記；不代表卡片真偽。」 |
| 同圖重複、盜圖無法保證 | 沒有做圖片比對 | 「照片由賣家提供，平台未比對。可以請賣家拍一張寫著今天日期的紙條合照。」 |
| 搶註 | 先登記的人佔號，真正持有人要走人工接管 | 「如果你的編號被別人登記了，附上照片申請接管，客服會審核。」——並把處理時間講實話 |
| 裸卡沒有唯一性 | 唯一約束只作用在有編號的卡 | 「沒有鑑定編號的卡，無法防止重複登記。」 |
| 沒有評價、沒有成交紀錄 | 成交在站外，平台不知道 | 不要做看起來像評價的分數；只顯示事實（加入日期、登記張數、檢舉處理結果） |
| 沒有行情 | 沒有成交資料 | 不顯示「市值」「收藏總值」這類數字；參考價明確標為「賣家自填」 |
| 人少 | 冷啟動 | 不灌假數字；首頁不放「已有 N 人」直到數字好看 |

**媒體上的卡牌相關詐騙與倒閉事件**可以當作「為什麼要登記、為什麼要查官網」的背景，
但**不要替未具名的案件指名任何平台**，也不要暗示「用我們就不會被騙」。

## 8. 查不到或沒驗證的

- 卡拍拍收藏冊是否有「對外分享連結」：網路補查只確認它有收藏冊與漲跌，沒查到分享功能，**不代表沒有**。
- cardbase.io 的 Pool Calculator 實際內容、是否已在台灣推 zh-TW：沿用 `cardbase-comparison.md`，本次未重查。
- 各 FB／LINE 社團的版規與是否允許外部連結：讀不到，要自己加入後看。
- 代送業者是否願意推薦外部平台：沒有訪談資料，是本文件的假設。
