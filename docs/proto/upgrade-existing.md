## 這份原型在回答什麼

任務只挑「**你已經有這個功能，但可以做得更好**」的那幾項。
所以每一項都是**兩具 393px 手機並排**：左邊是讀碼確認過的現況，右邊是改良後。
沒有對照就看不出價值 —— 這是這份原型唯一的結構原則。

第二層（另一條路、要換商業模式、要法律決定的）在最後一區，**列出來但不做互動**，29 項。

**⚠️ 讀「現況」時要知道的一件事**：這一輪動手時，工作區裡有**另一條線未提交的修改**
（`MarketPage.vue`、`MyCardsPage.vue`、`refprice.ts`、`public.ts` 等，見 `git status`），
它做的是 CardBase A-1／A-2 的**顯示紀律**（排序標籤、卡冊總值文案）。
這份原型的四項跟那條線**不重疊**：第二項做的是 A-3 的**外部錨點**，不是文案。
原型裡的「現在」以「有沒有錨點／有沒有成本基礎／入口開不開」為準，這三件事在兩個版本裡都還沒有。

## 四項的現況與改良後差在哪

### 一 · 登記卡片：手填 → 拍照辨識

| | 現在 | 改良後 |
|---|---|---|
| 卡片身分 | 手填卡名／系列／卡號，或從目錄挑 —— 而**目錄最準的搜法是日文卡名** | 拍標籤 → 讀出 `SV4a-349` → 餵進**既有的**目錄查詢 → 使用者從候選裡點選 |
| 鑑定編號 | 照著卡殼抄 8 位數 | **條碼**（有校驗、確定性、零邊際成本），不是辨識 |
| 一次幾張 | 一張。註解原文「要登記三張就走三次」 | 一樣一張 —— **這一項沒有改，批次表單會讓編號跟卡對不上** |
| 失敗 | 不存在（沒有這條路徑） | 三種都做出來了：條碼讀不到、兩個來源不一致、服務掛了 |

原型上方有失敗情境切換鈕，三種都點得下去。**核心是：這條路徑不可以擋住登記。**
服務掛了就整塊收起來、退回手動流程，一個字都不提辨識這件事。

出處：`src/pages/CardUploadPage.vue:33-45,206-220`、`src/lib/tcgdex-catalog.ts:8-24`

### 二 · 參考價：賣家自己填 → 有量級檢查

| | 現在 | 改良後 |
|---|---|---|
| 賣家端 | 一個 `type="number"`，後端只檢查上限 `10,000,000`，**零交叉檢查** | 即時提示「這個數字跟市場行情差幾倍」，**只提示不硬擋**，送出鈕照樣能按 |
| 合理帶 | 沒有 | **按鑑定等級開的**（裸卡 0.6–1.8×、PSA 10 1.3–6×、BGS 9.5 1.2–5×）—— Cardmarket 報的是 RAW 價 |
| 波動 | 沒有 | `avg30 / avg7` 超過 1.5 或低於 0.67 時標「劇烈波動中」 |
| 買家端 | 折數標籤直接印，分母是賣家自填的數字 | 量級沒過的掛單**不印折數、不進排序與精選區**；**買家永遠看不到那個外部價** |

原型上方可以換卡（31 張全部）、改價格，兩具手機同步變。

出處：`src/pages/CardUploadPage.vue:273-279`、`server/src/card-cert.ts:85`、`docs/research-card-pricing.md §四`

### 三 · 卡冊：加上「我當初花了多少」

| | 現在 | 改良後 |

## 三個要拍板的結論

### 拍照辨識：做得到，但要拆成三段，而且有一段做不到

- ✅ **鑑定編號 → 走條碼，不要走辨識。** PSA 新標籤背面 QR、舊標籤正面一維條碼。
  這一欄是 `unique(grader, cert_no)` 的鍵，讀錯一位就是把別人的卡擋掉 —— 不交給會猜的東西。
- ✅ **卡片身分 → 用現成的目錄查詢。** 2026-09-06 本機實測：
  `GET /v2/ja/cards?id=eq:SV8a-237` 回 `テラパゴスex`、`?name=like:リザードン` 回 49 筆。
  **價值不在省下抄 8 位數，在讓賣家不用會打日文。**
- ❌ **「拍卡面就認出是哪張卡」做不到。** 查證過 TCGdex 的篩選文件：
  它是欄位查詢系統，**沒有反向圖片搜尋、沒有感知雜湊**，只有 `eq:` / `like:` / `gt:` 這類條件。
  能拍的是**標籤**（有文字），不是卡面。要做卡面比對得自己建圖庫與雜湊索引 —— 那是另一個題目。
- ⚠️ **最大的未知：標籤上的套牌到底印什麼。** 英文名（`SHINY TREASURE EX`）還是代碼（`SV4a`）？
  `docs/ai-opportunities.md` 自己標了這是整個提案的前提而且沒查。
  **動工前第一件事是拿三張真實的日版 PSA 卡拍照。一小時，而它決定 3–4 週要不要花。**
- ⚠️ **離線只做得到一半，而 iOS 是貴的那一半。** 條碼在 Chrome／Android 有原生 `BarcodeDetector`；
  **iOS 上所有瀏覽器都是 WebKit，全部沒有這支 API**（2026-09 查證仍然如此），要帶 zxing-wasm 約 250KB ——
  而這個 repo 的前端只有三個 runtime 依賴。標籤文字**離線做不到**：tesseract.js 要 2–4MB wasm，
  而且它只吐文字，不會告訴你「這串字是哪個欄位」。

**成本**：Opus 5 單張 NT$1.23，一個 60 張卡的池 NT$74 —— 是那個池票收的 **0.12%**。
不建議降到 Haiku 4.5（影像上限 1568px，會把 commit `970e0a4` 自己量出來的那級餘裕丟掉）。
**工期 3–4 週，其中約一半跟辨識無關。**

**但它現在不是最急的一項**：P-5 實測正式站 32/32 是假池 ——
瓶頸不是「賣家嫌登記麻煩」，是「一個賣家都還沒有」。
門檻：≥3 個真實賣家且有人抱怨過登記流程，或單一賣家一次要登記 20 張以上。

### 成本基礎：我傾向 A 版（只顯示支出）

**A 版贏在一件事：它顯示的每一個數字都站得住。**
支出是帳本裡的真實紀錄，收藏合計是賣家標示而且旁邊寫著「其中 N 張未標示」。
兩個數字各自誠實、並排放著 —— 使用者自己會做那個減法，而那個減法是**他做的，不是平台做的**。

**B 版把一個真實的分子（支出）跟一個沒有依據的被減數（`Σ refPrice`）綁在一起**，
產出一個看起來很權威、分母卻是空的數字。使用者會對那個差額產生真實的情緒，
而它隨時可能因為某個賣家改了一次標價就跳動幾千點。
把原型切到「抽贏了」看一下 —— **B 版在贏的時候讀起來像投資報表，那正是問題。**

**但 A 版不是逃避**：拒絕加總一組使用者自己看得到的數字是一種假裝（錢包頁已經逐筆列著）。
A 版做的是**把加總做完（誠實），但不做那個不可靠的減法（紀律）**。

**硬前提**：這一項要等第二項（量級檢查）先做完。在收藏合計站得住之前做成本基礎，
等於把現有的問題放大 —— 而 B 版放大得最厲害。

### 公平性入口：按說服力排序

1. **池詳情的「驗證」分頁** —— 唯一「使用者已經在懷疑的那一刻」，他人在池頁上正在決定要不要掏點數。
   那一塊**本來就留著**，只被拔掉兩個連結，放回去成本最低。
2. **開卡結果頁** —— 這四個裡**最被低估**的。剛開完卡那一秒是整個產品懷疑心最強的一刻，
   「你抽到的是第 137 號籤，而它開賣前就排好了」比任何說明頁都有力。
3. **首頁** —— 要克制。三行的區塊加一個連結就夠，重點是**它存在**。
4. **「我的」選單** —— 不負責說服，負責讓看過的人找得回去。

**⚠️ 但不要看到這一條就直接翻布林值。** `src/lib/config.ts:14-29` 有一整段說明：
當初關掉是因為**使用者要求「先收起來，之後再展示」**。那是**展示閘門**，不是技術問題 ——
打開它是**使用者的決定**。這份原型能做的只有把「打開之後長什麼樣」擺出來，讓那個決定有東西可看。

**代價**：一個布林值 ＋ 七處入口露出。頁面本身一行都不用寫。
唯一要順手做的是 `PoolProof.vue` 那段隨開關換寫法的文案要換回來。
