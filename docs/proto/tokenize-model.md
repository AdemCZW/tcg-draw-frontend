## 這是什麼

使用者看完 Renaiss 的拆解之後說「可以有可以提升或參考的地方都給我製作 demo」、
「先給我製作就對了，最後要不要我自己會決定」。

**所以這份原型把 Renaiss 那一套完整做出來，包含分析文件裡判定「不該做」的部分。**
做原型沒有法律後果 —— 那是原型，不是營運。這份東西的用途是**讓使用者自己點過一遍再決定**，
不是替他決定。

⚠️ **另一條線的原型是 [`chain-anchor.html`](chain-anchor.html)**（只錨定證據、不碰資產）。
兩份是**並排比較**用的，這一份沒有動它的任何檔案。

## 哪些是真的、哪些是模擬

| | 狀態 |
|---|---|
| **SHA-256** | **真的。**純 JS 實作，開頁時跑一次 `sha256("abc")` 的標準答案自我測試，結果印在畫面最上方。 |
| **Merkle root 與 inclusion proof** | **真的。**按「產生 Merkle root」是把那 8 張卡真的做成一棵樹；按「驗證這張卡在不在承諾的卡池裡」是真的沿著兄弟雜湊往上算回 root。 |
| tx hash、合約名稱、tokenId、錢包地址 | **模擬。**本機亂數字串，重新整理就沒了。 |
| USDT 餘額、帳本 | **模擬。**純前端狀態，沒有後端、沒有 localStorage。 |
| 抽選的隨機性 | **`Math.random()`，而且畫面上明講。**因為 Renaiss 那邊沒有東西可以模擬 —— 見下方。 |
| 卡名、cert、估值 | **編的。**Tier 區間對齊 Renaiss PANDORA 48 的公開標示。 |
| 售價與標示 EV（28／48／88） | **一手抄來的**（renaiss.xyz/gacha，2026-09-06）。 |

## 四個分頁

### 1. 流程（五步）

每一步都是可以按的，狀態會變，右邊（手機是下面）是**全域帳本**，
記著每一筆錢從哪個帳戶到哪個帳戶。

| 步驟 | 做到什麼 |
|---|---|
| **0 入金** | 自託管錢包 → 站內地址 300 USDT。這是整條線的入口。 |
| **1 代幣化** | 1a 8 張 PSA 卡進第三方保管庫 → 1b `CollectibleInventory.mint()` 鑄 8 顆 ERC-721（**平台這時要先掏 $2,235 買存貨，帳本上平台餘額會變負的**）→ 1c `safeTransferFrom` 把代幣轉出到自託管錢包（示範「平台管不住它了」）。 |
| **2 抽包** | 選機台（28／48／88，附標示 EV 與 ×85% 之後的淨值）→ 產生並公開 Merkle root → 付 USDT 抽 → **驗 Merkle proof（真的驗）** → 「試著驗證抽選本身」（會撞牆，那是重點）。 |
| **3 即時買回** | 選一顆代幣，**平台估值有一根滑桿**，買回價 ＝ 估值 × 85%。按下去平台掏 USDT 買回自己送出的獎品，代幣回平台庫存。 |
| **4 二級市場** | 掛賣 → 模擬成交 → 賣方拿 98%、平台抽 2%。**另有「提領到自託管錢包」** —— 錢真的離開站內。 |
| **5 贖回實體卡** | burn 代幣、保管庫出貨、代幣總量 −1、平台庫存永久 −1（所以要補貨）。 |

**每一步都印「錢從哪來、到哪去」**，而且每一步底下都有可以展開的對照與法律位置
（`rules.md` 的兩條紅線、`HANDOFF.md:25` 的 70% 回購歷史、條款與產品不一致那一段）。

**步驟 3 的滑桿是刻意的**：`rules.md` 第四節寫「平台掏錢買回會變成印鈔票 —— 賣家可以把價格喊高再自己回收」。
那根滑桿把那句話變成手可以撥的東西：買回率永遠是 85%，但分母是平台自己定的。

**步驟 2 的「試著驗證抽選」也是刻意的**：它不會給你答案，它會告訴你
Renaiss 的 `docs/contracts.md` 五組合約裡沒有任何一個跟 VRF／randomness 有關，
沒有 seed、沒有 commit、沒有 reveal、找不到驗算頁。
**這個原型模擬不出它，因為它沒有公開任何機制。**

### 2. 並排對照

四個主題，左右各一欄：

1. 使用者付什麼、拿到什麼、能不能換回錢
2. 平台的收入來源（**含一條對 VaultDraw 不客氣的事實：現在的商業模式是空的**）
3. 公平性怎麼證明（VaultDraw：manifest_hash ＋ drand 未來輪次 ＋ 可重算；Renaiss：只有 Merkle root）
4. 平台承擔什麼風險

外加一張一頁摘要表。所有 VaultDraw 那一欄都附檔名與行號。

### 3. 買回的現金流試算

**這一頁在回答「即時買回 ＝ 平台變成做市商，要準備多少存貨與現金」。**
所有假設都是輸入框，每個結果旁邊都印著算式。

預設假設（可改）：

| 參數 | 預設 | 依據 |
|---|---|---|
| 每日抽包數 N | 500 | 我設的小規模基準 |
| 平均包價 P | $48 | PANDORA 48（一手） |
| 標示 EV ÷ 售價 | 108% | $51.82 ÷ $48（一手） |
| 抽完立刻賣回的比例 | 40% | **我猜的，沒有任何數據** |
| 買回率 | 85% | 商品頁 `Instant buyback 85%`（一手） |
| 買回的卡平均幾天再賣掉 | 14 天 | **我猜的，沒有任何數據**（最關鍵的一條假設） |
| 補貨前置天數 | 30 天 | **我猜的**（收卡＋送 PSA＋入庫） |
| Tier S 上限單價／機率 | $1,500／1% | 商品頁 Tier 表（一手） |
| 進貨成本率 | 估值 × 80% | **我假設的**，Renaiss 沒有公開進貨成本 |

算式：

```
每日票收        R = N × P
每日買回支出    B = N × 賣回比例 × (P × EV比) × 買回率
壓在買回庫存    = B × 再賣出天數
單日大獎緩衝    = (λ + 2√λ) × Tier S 上限 × 買回率，λ = N × S機率   （Poisson 近似）
補貨存貨張數    = N × (1 − 賣回比例) × 補貨前置天數
補貨存貨金額    = 張數 × (P × EV比) × 進貨成本率
合計準備金      = 買回庫存 + 大獎緩衝 + 補貨存貨
```

**預設值下的結果：每天淨現金 +$15,187（票收的 63%），但合計準備金 $508,704。**
也就是說：**要先躺著大約 21 天票收的錢，才做得起這個模式。**
把 N 換成它新聞稿的單日 $700,000（÷$48 ≈ 14,583 包／天），準備金會跳到約 $1,483 萬。

**一個反直覺但重要的發現，原型會直接告訴你**：
把「立刻賣回」拉到 100%，**每日損益仍然是正的** ——
因為 EV比 × 買回率 = 108% × 85% = **91.8% < 100%**，平台賣回一包只吐回售價的 91.8%。
**壓力不在損益表，在準備金與存貨周轉。**
要讓損益真的翻負，那個乘積要超過 100%（例如 EV 120% × 85% = 102%）——
原型有一顆按鈕直接切過去看。

**沒有算的成本**（全部只會讓需要的錢更多）：gas、USDT 出入金、第三方 Vault 保管費、
PSA 送鑑成本與失敗率、退貨、詐欺、卡價下跌造成的存貨減值。

### 4. 決策資訊

跟著原型走的事實，不是免責聲明：法域（BVI vs 台灣）、`rules.md` 的兩條紅線逐字、
`HANDOFF.md:25` 的 70% 回購歷史、規模數字彼此對不上的那張表、
產品與條款不一致（商品頁印 85%／`/terms` 沒寫）、以及**查不到的東西**單獨一塊。

## 這份原型刻意沒有做的事

- **沒有做決定。**每一條「不該做」的判定都留在 `vinciworld-comparison.md` 第四節 D，
  這裡只把那些功能做出來讓人點。
- **沒有把查不到的東西補滿。**贖回運費、買回時間窗、隨機數來源在畫面上都標著「查不到」，
  而不是填一個看起來合理的數字。
- **沒有模擬無限池。**本原型的卡池是固定 8 張 —— 有「全部」才給得出 Merkle proof。
  這個簡化本身就寫在畫面上，因為它正好是「可驗算性需要固定總量」那個論點的示範。
