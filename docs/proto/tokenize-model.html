Renaiss 模式 —— 完整走一遍

把 renaiss.xyz 那一套（代幣化 → 抽包 → 即時買回 → 站內市場 → 贖回實體卡）做成可以點完的原型， 每一步都印出錢的流向，並且跟現在的 VaultDraw 並排。 對照資料來自 docs/vinciworld-comparison.md（調查日 2026-09-06）。

全部是模擬。 這個檔案沒有連任何鏈、沒有錢包、沒有金鑰、沒有送出任何交易（含測試網），也沒有花任何錢。 畫面上的 tx hash、合約呼叫、代幣 ID、USDT 餘額全部是本機產生的字串，重新整理就沒了。 唯一真的在跑的密碼學是 SHA-256 與 Merkle root／proof —— 那一段在你的瀏覽器裡真的算，可以自己改資料看它壞掉。

同一件事，兩種做法並排。左邊是現在的 VaultDraw（讀碼，行號為 2026-09-06 的 main）， 右邊是Renaiss 模式（一手查證或業者宣稱，標在每一條旁邊）。

一、使用者付什麼、拿到什麼、能不能換回錢

VaultDraw 現況

  • 付：點數。1 元＝1 點，站內用。目前連儲值都還沒接（TopupPage.vue:18 直接 return），只有 POST /admin/grant 手動發放。
  • 拿到：一張真的卡進卡冊，四條路 —— 留著（有寄存期限）／申請出貨／賣回給開池的賣家／上架市場。
  • 能不能換回錢：不能，而且沒有那條程式路徑。錢包 API 只有 GET（server/src/routes/wallet.ts:10-17）；全 repo 搜 withdraw／payout／cashout 在 server/src 零命中。
  • 賣回的價格誰定：賣家在開賣前宣告的絕對金額，封進 commit 雜湊（fairness.ts:69-76），開賣後改了對不上。錢從賣家帳戶出（pool-settlement.ts:411,415）。

Renaiss 模式 一手

  • 付：BNB 鏈上的 USDT。從交易所買 USDT(BSC) → Top Up 轉進站內地址。
  • 拿到：一顆 ERC-721，對應一張存在第三方 Vault 的 PSA 卡。可轉移、可掛賣、可贖回實體。
  • 能不能換回錢：能。85% 即時買回或二級市場賣掉 → USDT → 自託管錢包 → 交易所 → 法幣。
  • 賣回的價格誰定：平台，按它自己的 platform valuation × 85%。而 /terms 裡完全讀不到買回方案 —— 產品在做的事沒有寫進條款。
來源：/gacha 商品頁 Instant buyback 85%、docs typescript-sdk buybackGacha()、/terms（皆一手，2026-09-06）。

二、平台的收入來源

VaultDraw 現況

  • 抽卡抽成 0% —— pool-settlement.ts:30 PLATFORM_FEE_RATE = 0，splitTicket() 裡的 if (fee > 0) 永遠不成立。
  • 市場手續費 0% —— 成交只有兩筆對沖分錄（orders-service.ts:82-84），沒有抽成那條分錄。
  • 目前唯一會進平台帳戶的錢：沒收的保證金（orders-service.ts:89-90）。也就是說現在的商業模式是空的，這是要面對的事實，不是優點。

Renaiss 模式 一手＋推論

  • 抽包的價差。標示 EV 約售價的 108–109%，但只給 85% 即時買回 → 立刻變現的淨值約 92–93%。差額留在平台。〔算術是我做的〕
  • 二級市場 2% —— /terms：2% of the Platform Valuation or sale amount。
  • 未來：Lending／Borrowing 標 coming soon；保管費條款寫 may be introduced in the future。
  • 不是發幣：截至查證日無原生代幣。
左邊那條「商業模式是空的」很重要：兩邊不是「誰比較貪」，是一個已經有收入設計、一個還沒有。

三、公平性怎麼證明

VaultDraw 讀碼

  • 獎品清單承諾：manifest_hash，v4 含 grader／grade／certNo／refPrice／buyback／variantId（fairness.ts:129-148）。
  • server seed：randomBytes(32) ＋ assertSeedEntropy()（pools-service.ts:159,162）。
  • commit：SHA256(server_seed ‖ manifest_hash)，開賣前公開（fairness.ts:163-170）。
  • client seed：drand 的未來輪次（FUTURE_ROUNDS = 4，約兩分鐘後）—— 開池當下那個數字還不存在。
  • reveal：售罄後才公開 seed（pools-service.ts:833-838），之前一律回 null。
  • 自己重算：verifyReveal() ＋ FairnessPoolPage.vue，在瀏覽器逐位比對整條籤序。
    但 config.ts:30 FAIRNESS_UI = false —— 站內入口全關

Renaiss 模式 一手＋查不到

  • 獎品清單承諾：Merkle root，A fingerprint of this pack's card pool, published on-chain before the drop. —— 這一半跟 VaultDraw 等價。
  • 隨機數來源：查不到 docs 的 contracts.md 列出五組合約 （TokenVendingMachineV3、CollectibleInventory、RenaissRegistry、OrderBook、TimelockController）—— 沒有任何一個跟 VRF／randomness／fairness 有關。
  • 沒有 seed、沒有 commit、沒有 reveal、沒有具名的 VRF 供應商、找不到給玩家重算的驗算頁。首頁那句 every result is provably random and verifiable on-chain 目前只有這句話本身。
  • 而且它換不回來了：Gacha V2 改成無限池之後，「固定籤數的一個排列」不存在， 事後公開種子重算整條序列這件事在數學上就沒有對象。
在「流程」分頁的步驟 2 可以親手驗一次 Merkle proof，也可以按下「試著驗證抽選」看它撞牆 —— 那個撞牆是重點，不是 bug。

四、平台承擔什麼風險

VaultDraw 讀碼

  • 買回的錢平台完全不出。只有賣家↔卡主兩個帳戶；賣家的保留額付不出來就整筆 rollback（SELLER_UNFUNDED）。平台沒有做市商部位，也沒有存貨。
  • 不代管實體卡（migrations/021:57,132-138）—— 也就是不承擔保管與遺失。
  • 承擔的是履約風險：託管、保證金、72h 出貨、7 天鑑賞、爭議裁決、違約累積（escrow.ts:20-38）。這一塊是平台自己扛的。
  • 護欄夾的是別人的承諾：保底回饋率上界 100%（印鈔）、下界 25%（economics.ts:48-50,129-132）。

Renaiss 模式 推論

  • 即時買回 ＝ 平台變成做市商。每一筆買回都是平台自己的現金流出，而且是即時的；買回的卡要重新賣出去才回本。
  • 要準備多少現金與存貨，去「買回的現金流試算」分頁自己調參數。那一頁把假設全部攤開讓你改。
  • 定價權與付款義務同時在自己手上 —— 85% 的分母是平台自己的 valuation，而條款沒有寫死它。這是 rules.md 第四節講的「印鈔票」那個結構。
  • 實體卡風險外包：條款寫 Assets are stored by third-party Vault providers、We do not provide custody or security services。

「即時買回」把平台變成做市商：出價、收貨、壓庫存、等下一個買家。 這一頁把那件事算給你看。所有假設都是輸入框，全部可以改 —— 下面每個數字旁邊都印著它的算式， 你不同意哪一個假設就直接改哪一個。

假設

這個試算用了什麼假設（也就是它哪裡會錯）

  • 買回是即時的、再賣出是延遲的。整個現金壓力來自這個時間差。壓在庫存裡的錢＝每日買回支出 × 再賣出天數。這是最關鍵的一條假設，而「再賣出天數」我沒有任何 Renaiss 的實際數據，預設 14 天是我猜的。
  • 把「立刻賣回」當成當天發生。真實情況會分散在幾天內，尖峰會比這裡算的低一點、但長尾更長。
  • 大獎緩衝用 Poisson 近似（λ ± 2√λ），只抓「同一天多開出幾張 Tier S」的抖動，沒有模擬連續多天的壞運。
  • 無限池要持續補貨。賣出去而沒有被賣回的卡是永久淨消耗，所以要備 每日淨消耗 × 前置天數 的存貨。
  • 沒有算：gas、USDT 出入金成本、第三方 Vault 保管費、PSA 送鑑成本與失敗率、退貨、詐欺、價格下跌造成的存貨減值。這些全部只會讓需要的錢更多，不會更少。
  • 「照它的新聞稿」那顆按鈕用的是 GlobeNewswire 2026-02-11 那則的單日交易量 $700,000 ÷ 包價，換算成包數。那個數字是業者自述，沒有第三方查核，而且跟它其他公開數字對不上（見決策資訊分頁）。

這些事實會影響「要不要做」，所以放在原型裡面，不是放在對話裡。 每一條都標了它的證據等級，體例沿用 docs/vinciworld-comparison.md。

docs/rules.md 記著的兩條限制（逐字）

  • 第一節：「點數不能換回現金。這不是產品選擇，是法律紅線（刑法 266 條的對價關係）。」
  • 第四節：「平台買回自己送出的獎品在台灣是明文禁止的（電子遊戲場業管理條例第 14 條）」； HANDOFF.md:25 補上條號：第 14 條第 2 項第 2 款，禁止「買回提供給客人之獎品」。
  • 第四節同段還寫了第二個理由（跟法律無關）：「平台掏錢買回會變成印鈔票 —— 賣家可以把價格喊高再自己回收。」
