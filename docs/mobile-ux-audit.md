# 手機實機動線體檢（393×852）

日期：2026-08-31
範圍：**全站前台動線**，用 headless Playwright 逐條走完。`/seller/new`（開池）依交辦跳過。
驗證環境：`VITE_API_URL= npm run dev -- --port 5411`（mock 模式），
Chromium headless、viewport **393×852、`isMobile: true`、`hasTouch: true`**、DPR 3、iPhone UA。
mock 的登入＝形象頁按「登入」直接進站。

**本輪只做診斷，沒有改任何程式檔。** 唯一新增的是這份報告與 `docs/shots/mobile-audit/` 的截圖。

> 稽核期間 repo 一直在動：開始時 HEAD 是 `d54b435`，中途另一支 agent 連續推了 10 個 commit。
> **下面每一條都在 `0984e0f` 上重跑過一次、數字原樣貼上**（之後只多了 `57d2cc6`，
> 只改 `src/pages/pool/PoolOverview.vue`，不影響任何一條）。
> 中途被別人修掉的那一條列在最後的「稽核期間已被修掉」。

每一條的「量到的數字」都是 `getBoundingClientRect()` 對 852px 視窗算出來的：
`inView` 指整個元素在視窗內；負的 `top` 是在視窗上方，>852 的是在視窗下方。
按鈕位置一律先 `scrollIntoViewIfNeeded()` 確認它在視窗內、再按，
所以「按之後的捲動位移」是**頁面自己捲的**，不是測試框架捲的。

### M-1 市場買「需寄送」的卡：付完錢，畫面一個像素都沒變

**重現**
1. 登入 → 底部「市場」 → 點任何一張標「需寄送」的卡（例 `/market/l5`，太樂巴戈斯 ex UR，18,220 點）
2. 按最下面那條的「**買下 · 18,220 點**」（在視窗內，top 724）
3. 按「**確定買下**」

**量到的數字**（`0984e0f`，兩次獨立跑結果完全一樣）

```
按之前  scrollY 0  docH 1275  餘額 "100,000,000 點"  買下鈕 top 724 inView:true
按之後  scrollY 0  docH 1385  餘額 "100,000,000 點"  買下鈕 → 不存在
        「18,220 點已凍結」  top 959  inView:false   ← 視窗底下方 107px
        「看這筆訂單」        top 1066 inView:false   ← 視窗底下方 214px
        toast 元素數：0      頁面沒有自動捲動（0 → 0）
```

交易本身是對的：`[ga] market_buy_success`，`/me/orders` 進去看得到
「託管中 18,220 / 進行中 1 / 已鎖點・等出貨 / 賣家出貨期限 剩 2 天」，全部正確。

**使用者會怎麼理解這個畫面**
他按了「確定買下」，然後：卡圖一樣、價格一樣「18,220 點」、
「需寄送，點數先託管」那段文案一樣、**頭部餘額還是 100,000,000**，
唯一的變化是最下面那條「買下」不見了。
他的結論只會是兩個之一：「這站壞了」或「我沒買到，按鈕消失了」。
接著他會回市場、發現這張卡不見了，然後開客服單問「我到底有沒有買」。
截圖：`docs/shots/mobile-audit/M1-market-ship-buy-fullscreen.png`

**為什麼庫內轉移沒事、只有這條有事**
`src/pages/MarketListingPage.vue` `buy()`：
`vault` 那條 `setTimeout(() => router.replace({ name: 'cards', ... }), 1400)` —— 真的把人帶走，
落地還帶 `?new=<stashId>` 讓卡冊把那張標起來，並跳「這張卡已經在你的卡冊裡」（實測 toast top 739，inView）。
`ship` 那條只有 `done.value = 'ship'`，**沒有導頁、沒有捲動、沒有 toast**，
而 `.result` 這塊是接在詳情 `<section>` 後面的流內元素（樣板約 316 行），
在 393px 上那個位置就是 959px。同時 `!done` 把 sticky 結帳列整條移除，畫面反而更空。

**同一段程式的另外一條（推論，未實測）**：`delisted`（賣家自己按「下架收回」）
用的是同一個 `.result` 位置、同樣不導頁，應該有一模一樣的症狀。
mock 帳號抓不到「自己的掛單」，沒測到。

### M-6 接受交易邀約：畫面說「12,000 點已完成移轉」，餘額不動

**重現**
1. `/me/offers` →「收到的」分頁 → 第一筆（小明，噴火龍 ex UR，12,000 點）按「**接受**」
2. 按「**確認接受**」

**量到的數字**

```
接受前  餘額 "100,000,000 點"   狀態 [等待回覆, 等待回覆, 已婉拒]
接受後  餘額 "100,000,000 點"   狀態 [已成立,   等待回覆, 已婉拒]
        畫面出現「已接受 小明 的邀約，12,000 點與卡片已完成移轉。」（在視窗內，看得到）
再按「重新整理」            餘額 "100,000,000 點"
用底部導覽切到卡冊（SPA）    餘額 "100,000,000 點"
（卡片那半是對的：噴火龍 ex UR 確實從卡冊消失了）
```

**這條不是 mock 假象。** `src/lib/social.ts` 的 `offers.accept()`
正式那條是 `return http('/v1/social/trade-offers/${id}/accept', …)` ——
**沒有呼叫 `applyWallet()`**（`src/lib/api.ts` 261 行那個 helper，
抽卡、買掛單、回收、讀錢包都有呼叫，只有 social 這支沒有），
而 `src/pages/OffersPage.vue` 的 `accept()` 之後只 `await load()` 重抓邀約列表，
從頭到尾沒有任何一行去更新 wallet store。
所以就算伺服器有把新錢包回在 response 裡，前端也會丟掉它。
`useWalletStore` 沒有輪詢、沒有全域刷新，只能靠 `applyServer()` 被呼叫。

**使用者會怎麼理解這個畫面**
畫面明明白白寫「12,000 點與卡片已完成移轉」，頭部的餘額卻一動也不動。
他要嘛以為錢沒進來（去開客服單），要嘛以為那行字是假的。
這跟使用者親手抓到的「登入後餘額顯示 0」是同一種病：**有人改了錢，但沒有人去拉錢包。**

**建議一起檢查的同類（推論，未逐支驗）**：`src/lib/social.ts` 裡其他會動錢的動作
（`offers.decline` 對送出方是「收回」、可能要解凍）也走同一支 `http`，同樣沒有 `applyWallet`。
