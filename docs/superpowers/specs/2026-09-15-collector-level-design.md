# 收藏家等級（徽章）設計

日期：2026-09-15　狀態：使用者已同意設計，待審閱本文件

## 目的

第一階段沒有金流，不送錢包點數。改用「收藏家等級」給使用者登記鑑定卡的動機，
並讓公開卡冊、賣家頁有可以炫耀、可以分享的東西。等級跟「台灣鑑定卡的公開登記簿」
定位一致：登記越多鑑定卡，等級越高。

## 名詞

- **收藏積分**：決定等級的分數。跟錢包的「點數」（points_ledger）完全分開：
  不能花、不能轉讓、不能兌換任何東西，畫面上一律稱「收藏積分」，不寫「點」。
- **等級**：由收藏積分總和查表得出。

## 規則

### 加分

| 事件 | 誰加 | 分數 | 何時入帳 |
|---|---|---|---|
| 登記一張有鑑定編號的卡 | 登記人 | +1 | 登記成功當下 |
| 站內市場買到一張卡 | 買家 | +1 | 訂單結案且結局是成交（買家確認收貨或鑑賞期滿） |

不加分：裸卡（沒有鑑定編號）、玩家互換、賣家成交、抽卡抽到的卡。

「有鑑定編號」的判準與既有唯一索引一致：正規化後 grader 與 cert_no 皆非空。

### 扣回

| 事件 | 扣誰 | 分數 |
|---|---|---|
| 登記的卡編號被檢舉成立 | 當初的登記人 | −1（抵銷那一筆登記分） |
| 買卡的訂單最後退款或取消 | 買家 | −1（抵銷那一筆成交分；若尚未入帳則不會有分可扣） |
| 登記人自己刪除登記 | 登記人 | −1 |

- 卡片賣掉或轉出**不扣**：等級不看卡冊現在有幾張。
- 同一筆來源只能加一次、扣一次（冪等）。沒有對應加分紀錄的事件不扣分。
- 總分顯示最低為 0。

第一階段沒有站內交易，實際上只有「登記鑑定卡」與其扣回會發生。

## 等級表

| 等級 | 門檻（收藏積分） | 名稱 |
|---|---|---|
| 0 | 0 | （不顯示徽章） |
| 1 | 1 | 新手收藏家 |
| 2 | 10 | 收藏家 |
| 3 | 30 | 資深收藏家 |
| 4 | 100 | 大師收藏家 |
| 5 | 300 | 傳奇收藏家 |

等級名稱不使用寶可夢官方用語（訓練家、冠軍等），避免被讀成官方授權。
門檻與名稱放在 `src/shared/`（前後端共用，照既有 sync-shared 流程同步到 server）。

## 顯示位置

1. **公開卡冊頁首**（`/u/:slug`，PublicCardbookPage）：徽章＋等級名稱。
2. **賣家頁**（`/sellers/:id`，SellerPage）：賣家名稱旁徽章。
3. **我的頁**（MePage）：徽章、目前收藏積分、「還差 N 分升到下一級」進度條；
   滿級時改顯示「已達最高等級」。

徽章是一個共用元件（例如 `CollectorBadge.vue`），吃等級數字，輸出圖形＋名稱。
行動版不用 emoji；圖形用 CSS／SVG 繪製，每級顏色與圖形層次遞進，
淺色與深色主題都要可讀。等級 0 不渲染任何東西。

## 資料設計（第二步，demo 通過後才做）

採「收藏積分流水帳」，比照既有 points_ledger 的做法：

- 新表 `collector_points`：`id`、`user_id`、`delta`（+1 / −1）、`reason`
  （`register-graded` / `register-revoked` / `register-deleted` / `market-buy` / `market-buy-reversed`）、
  `ref_id`（prize id 或 order id）、`created_at`。
- 唯一索引 `(user_id, reason, ref_id)` 保證冪等。
- 等級＝`sum(delta)` 取下限 0 後查表。
- 寫入點：
  - 卡冊上傳登記成功（server/src/routes/cardbook.ts）→ 有鑑定編號才寫 `register-graded`。
  - 檢舉成立、刪除登記 → 若存在對應 `register-graded` 且尚未抵銷，寫抵銷分。
  - 訂單結案為成交（orders 結案路徑，含掃描自動結案）→ `market-buy`；
    結案為退款／取消且已有 `market-buy` → `market-buy-reversed`。
- API：公開卡冊與賣家頁的既有回應加上 `collectorLevel`（只給等級，不給分數明細）；
  我的頁用本人端點回 `collectorPoints` 與 `collectorLevel`。

為什麼不現算：卡賣掉後擁有者會變，現算無法得知當初的登記人；檢舉扣回也需要留紀錄。

「檢舉成立」目前沒有專屬的資料狀態（檢舉走客服工單）。第二步需要決定由後台哪個動作
觸發扣回，列為實作計畫的一項，不在本 demo 範圍。

## 第一步：畫面 demo（本次範圍）

- 只在展示模式（MOCK，`VITE_API_URL=` 空）以假資料呈現，不動資料庫、不動後端。
- 做出：`CollectorBadge` 元件五個等級、公開卡冊頁首、賣家頁、我的頁的進度條。
- 提供一個能一次看到五個等級的檢視方式（例如既有設計頁或 mock 資料切換），方便使用者比較。
- 驗證：`npm run build` 通過；headless 或預覽在 375px 與桌機寬度截圖，淺色與深色各一。
- 使用者看過徽章樣子、名稱、門檻後，才進入第二步。

## 不做的事

- 不送錢包點數，收藏積分不能兌換任何東西。
- 不做排行榜（容易變成刷分目標，之後再議）。
- 不做等級帶來的功能解鎖（之後再議）。
